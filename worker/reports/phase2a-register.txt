4. Rate limiting and token key

Durable Object bindings:
- RL_CONTEXT_IP -> ContextRateLimiter, 100 / 60 seconds, key context|<ip>
- RL_SUBMIT_IP -> SubmitIpRateLimiter, 30 / 60 seconds, key submit|<ip>
- RL_SUBMIT_TOKEN -> SubmitTokenRateLimiter, 60 / 60 seconds,
  key submit|<sha256hex(token)>

Migration:
- [[migrations]] tag = "v1"
- new_sqlite_classes = ContextRateLimiter, SubmitIpRateLimiter, SubmitTokenRateLimiter

Behavior:
- One Durable Object per key; a single SQLite row holds count and window_start.
- Fixed 60-second window; over-limit is 429.
- Missing binding, thrown error, non-2xx object response, or malformed response
  fails closed with 503.
- The raw QR token is hashed with Web Crypto SHA-256 before it becomes a key.
  The binding and the object only receive the 64-hex digest.
- No log line contains the QR token: the registration path logs only
  name/code/constraint on errors and never logs URLs, bodies, or limiter keys.
  Tests also assert the raw token is absent from logs, responses, and writes.
  A scan of the Wrangler log found 0 token-shaped 64-hex strings.

Shared-constant check (step 2):
  The employee select was the module constant EMPLOYEE_COLUMNS =
  "id,full_name,departments(name),positions(name)", read inside loadEmployees().
  loadEmployees() is shared by two routes:
    - GET /registrants        (line 475 before the change)
    - GET /monthly-summary    (line 522 before the change)
  Because another route uses the same select, EMPLOYEE_COLUMNS was left byte-for-byte
  unchanged and /registrants was given its own string:

    const REGISTRANTS_EMPLOYEE_COLUMNS = `${EMPLOYEE_COLUMNS},employee_code`;

  loadEmployees() gained an optional third parameter, columns = EMPLOYEE_COLUMNS, so
  every existing call site still asks for exactly the original columns. Only
  /registrants passes the extended string. No other route's query changed.

Row mapping:
  employeeCode: employee?.employeeCode ?? null
  The internal employee map stores employeeCode: row.employee_code ?? null, so a row
  whose employee has no code yields null, never an empty string. When employee_code is
  not selected (all other routes), the value is simply never read.

reports/rollback-plan.md (new)
  - Who decides and executes (owner) and the trigger conditions.
  - What to stop first: remove the every-minute cron from wrangler.toml if it was
    ever added, and make sure Express auto-absent is enabled.
  - Two traffic-switch paths: A) run Express in production mode so it serves dist
    and /api on port 3001 (no code change; users get a new origin and must log in
    again because the cookie is host-only), B) keep hr-hub.pages.dev by changing
    the Pages function proxy to point at Express (a code change, needs owner
    approval, APP_ORIGIN and TRUST_PROXY_HOPS=1).
  - The PIN incompatibility, read from the real code: Worker stores
    hmacSha256(PIN_PEPPER, "<employeeId>:<pin>") as 64-char hex
    (worker/src/pin-rules.js, pin-verify.js); Express stores bcrypt and verifies
    with bcrypt.compare (server/routes/auth.js, server/pin-verify.js). bcryptjs
    returns false when the hash length is not 60 (checked in node_modules/bcryptjs),
    so every Worker-set PIN fails on Express, pins the user out after five attempts
    (423, 15 minutes), and never takes the "no PIN yet" branch because pin_hash is
    not null. Before rollback the owner must find rows whose pin_hash does not start
    with "$2", null those values, issue reset codes with the existing
    npm run issue:reset-code -- <employee_code>, and have each user set a PIN again
    through Express. No DROP/ALTER was written or run, and no Express change is
    proposed as part of this work.
  - Data compatibility table: which tables the Worker writes (auth_sessions,
    employee_credentials, pin_reset_codes, audit_logs, meeting_sessions,
    meeting_attendance, meeting_roster, meeting_types), and that Express can read
    all of them unchanged except the pin_hash format. Read-only tables are listed
    separately. Based on the schema list in worker/reports/phase2-spec-draft.md 3.8
    and the Phase 4a/4c parity results.
  - A plain list of what cannot be undone: PINs set on the Worker, a deleted Worker
    name (secrets cannot be read back), deleted audit rows, requests that never
    reached the database, and a missing backup.

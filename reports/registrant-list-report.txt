3. ENDPOINTS USED (both GET, read-only)
===============================================================================

  1) GET /api/meeting/dashboard?code=sup|monthly
     Used for: `statuses` (STATUS_LABELS order for the chips), `history.options`
     (round selector) and `current.key` (default round).
  2) GET /api/meeting/dashboard/registrants?code=sup|monthly&cycle=<key>
     Used for: `items[]` (name, departmentName, positionName, status, shift, time),
     `total`, `cycle.label`.

Both are Hono GET routes in worker/src/routes/meeting-dashboard.js (mounted at
/api/meeting/dashboard). Neither has side effects: the file's own header states the
dashboard GETs perform no auto-absent, no attendance writes and no audit insert.
The page sends no other request: `grep` over the file shows only those two `/api/...`
strings, and both go through a helper hard-wired to method GET.

===============================================================================
4. CONTRACT GAP (STOP CONDITION, REPORTED NOT PATCHED)
===============================================================================

The task asks for the employee code per registrant. The registrants endpoint does not
return one: each item is
  { name, departmentName, positionName, status, shift, time }
and the database read behind it selects only employee `id, full_name,
departments(name), positions(name)` (EMPLOYEE_COLUMNS in the Worker, identical in
server/routes/meeting-dashboard.js:410-430). Employee codes are selected only by
/api/meeting/roster (member/candidate rows), which lists the roster, not the actual
registrants - a different population, and matching on name would be guesswork.

Per the task's stop condition I did not change the Worker. The page therefore renders
the "รหัสพนักงาน" column from `item.employeeCode` when the API provides it and shows
"-" otherwise, which is the Worker's own convention for a missing value. As of this
build the column is always "-" until a field is added to the endpoint's response.
Owner decision needed (see open questions).
